A beginner's tutorial · three.js + GLSL

How the Lanzarote sea is drawn

The ocean in this project is one flat, square plane. It has no wave geometry at all. Everything you see on it, from the swell and the turquoise shallows to the surf and the whitecaps, is painted per pixel by a small shader. This page walks through that shader one layer at a time, using the real code from src/foundation/rendering/.

Before we start

What a shader is, in five minutes

Your graphics card draws every frame in two stages, and each stage runs a tiny program called a shader. Shaders are written in GLSL, a small C-like language.

  1. The vertex shader runs once for every corner (vertex) of a mesh. Its job is to say where that corner lands on the screen. Our sea plane has only 4 corners, so this runs 4 times.
  2. The fragment shader runs once for every pixel the mesh covers, and decides that pixel's colour. A sea filling half a 1080p screen means about a million runs, every frame, all in parallel.

All the interesting work on this page happens in the fragment shader. Each pixel asks a few questions ("where am I in the world?", "how far am I from the beach?", "what time is it?") and works out its own colour from the answers. No pixel can see its neighbours, which is why the shader recomputes everything from scratch for each one.

Three words you'll see everywhere:

WordMeaningExample here
uniformA value JavaScript hands to the shader. It is the same for every pixel in a frame.the time, the wind, the shallow colour
varyingA value the vertex shader passes down to the fragment shader, blended smoothly across the triangle.each pixel's world position
vec2 / vec3 / vec4Small vectors of 2, 3 or 4 numbers. Used for positions, directions and colours alike.vec3(0.92, 0.95, 0.96) is foam white

And the four GLSL functions that do most of the work:

FunctionWhat it does
mix(a, b, t)Blends from a (when t = 0) to b (when t = 1). Works on numbers and on colours.
smoothstep(e0, e1, x)0 when x is below e0, 1 when x is above e1, and a smooth S-curve in between. The workhorse for soft edges.
sin(x)The familiar wave, between −1 and 1. Add time inside it and it moves.
dot(a, b)For a point p and a direction d, dot(p, d) is how far along d the point is. That is how waves get a travel direction.

Step 1

A flat plane

The sea starts as the simplest mesh three.js can make: a square of two triangles, rotated to lie flat.

src/foundation/components/environment/Water.ts

load(_sunPosition: THREE.Vector3) {
  const waterGeometry = new THREE.PlaneGeometry(this.options.size, this.options.size);
  this.waterMesh = new THREE.Mesh(waterGeometry, new OceanMaterial());
  this.waterMesh.rotation.x = -Math.PI / 2;   // a PlaneGeometry stands upright; lay it down
  this.waterMesh.receiveShadow = true;        // the island casts shadows onto the water
  return this.waterMesh;
}

All the magic is in OceanMaterial. A material in three.js decides how a mesh's surface looks, and behind every material sits a vertex shader and a fragment shader.

Step 2

Borrow a material, then patch it

Writing a sea shader from nothing means also writing sunlight, sky reflections, shadows and fog. That is a lot of maths three.js already has in MeshStandardMaterial, its realistic, physically based material. So OceanMaterial extends it and slips a few extra lines into its shader.

src/foundation/rendering/OceanMaterial.ts

export class OceanMaterial extends THREE.MeshStandardMaterial {
  constructor(look: OceanLook = DEFAULT_OCEAN_LOOK) {
    // deep-water colour, very smooth (shiny), not metal
    super({ color: look.deepColor, roughness: 0.12, metalness: 0.0 });
    ...
  }
}

A low roughness makes the surface act like a mirror. Because the render pipeline sets scene.environment to a picture of the sky, a shiny surface automatically reflects that sky and shows a bright glint where the sun bounces off. We get both for free.

The patching happens in onBeforeCompile. three.js builds its shaders out of named chunks, written as #include <something>. Just before the shader is compiled, three.js hands us its source code as a string, and we use plain JavaScript .replace() to swap chunks for our own code:

this.onBeforeCompile = shader => {
  // 1. hand our uniforms to the shader
  Object.assign(shader.uniforms, this.oceanUniforms, {
    uTime: sharedUniforms.uTime,
    uWind: sharedUniforms.uWind,
    uCloudShadow: sharedUniforms.uCloudShadow,
  });

  // 2. vertex shader: remember where each point is in the world (step 3)
  shader.vertexShader = shader.vertexShader
    .replace('#include <common>', '#include <common>\nvarying vec3 vLzWorld;')
    .replace(
      '#include <project_vertex>',
      '#include <project_vertex>\nvLzWorld = (modelMatrix * vec4(transformed, 1.0)).xyz;'
    );

  // 3. fragment shader: our helpers, then colour, roughness, normal and shadow
  shader.fragmentShader = shader.fragmentShader
    .replace('#include <common>', `#include <common>\n${OCEAN_PARS_GLSL}`)
    .replace('vec4 diffuseColor = vec4( diffuse, opacity );', OCEAN_COLOR_GLSL)
    .replace(
      '#include <roughnessmap_fragment>',
      '#include <roughnessmap_fragment>\nroughnessFactor = mix(roughnessFactor, 0.85, lzFoam);'
    )
    .replace('#include <normal_fragment_maps>', OCEAN_NORMAL_GLSL)
    .replace(
      '#include <opaque_fragment>',
      'outgoingLight *= lzCloudShadow(vLzWorld.xz);\n#include <opaque_fragment>'
    );
};

Each replacement targets one spot in three.js's own pipeline:

<common>The top of the shader. We add our uniforms and helper functions here.
diffuseColorWhere the base colour is set. We swap in our own: deep, shallow or foam.
roughnessmapHow shiny the pixel is. Foam is matte, open water is glossy.
normal_fragment_mapsWhich way the surface faces. This is where the waves live.
opaque_fragmentThe final colour, after lighting. Cloud shadows darken it here.
Tip. To see the full list of chunk names, open node_modules/three/src/renderers/shaders/ShaderLib/meshphysical.glsl.js. The replace strings must match that file exactly, which is why this technique can break when three.js is upgraded.

One more detail: customProgramCacheKey() returns 'lz-ocean'. three.js reuses compiled shaders between materials of the same type, and this key tells it that our patched version is different from a plain MeshStandardMaterial.

Step 3

Tell each pixel where it is

The fragment shader doesn't know where in the world its pixel is. The two vertex-shader lines above fix that. transformed is the vertex position inside the mesh; multiplying by modelMatrix turns it into a world position, which we store in the varying vLzWorld.

The GPU then blends vLzWorld across the triangles, so every pixel of the sea receives its own exact world position. From now on the shader uses vLzWorld.xz, the position on the ground plane (east–west and north–south), as the input to everything. Because the patterns are tied to world positions, they stay fixed to the sea while the camera moves.

Step 4

A clock and a wind

Movement needs time. One shared object holds the uniforms that every weather-related shader in the app uses: the ocean, the cloud shadows on the terrain and the gulls.

src/foundation/rendering/sharedUniforms.ts

export const sharedUniforms = {
  uTime: { value: 0 },
  // Wind on the ground plane (x = east, y = south), in metres per second.
  uWind: { value: new THREE.Vector2(5, 0) },
  // 0 = no cloud shadows, 1 = full strength.
  uCloudShadow: { value: 0.35 },
};

Every frame, the render pipeline adds the elapsed seconds to the clock:

src/foundation/rendering/RenderPipeline.ts

render(camera: THREE.Camera): void {
  const delta = Math.min(this.clock.getDelta(), 0.1);
  sharedUniforms.uTime.value += delta;
  ...
}

Uniforms are wrapped as { value: ... } on purpose. The ocean's shader holds a reference to the same object, so changing .value in JavaScript updates the shader on the next frame with no extra work. One clock moves the waves, the clouds and the birds together.

Inside the shader, the wind vector is split into a speed and a direction:

float lzWindSpeed = length(uWind);                       // metres per second
vec2 lzWindDir = lzWindSpeed > 0.01 ? uWind / lzWindSpeed // a direction of length 1
                                    : vec2(1.0, 0.0);      // calm day: pick east

Step 5

Noise: randomness that looks natural

Real water is never perfectly regular. To break up patterns, the shader uses noise: a function that returns a "random" number between 0 and 1 for any position, but changes smoothly as you move. It is built in three layers.

src/foundation/rendering/shaderChunks.ts

// 1. Hash: a jumbled number for a point. Same input, same output, but no visible pattern.
float lzHash(vec2 p) {
  p = fract(p * vec2(123.34, 456.21));
  p += dot(p, p + 45.32);
  return fract(p.x * p.y);
}

// 2. Value noise: hash the four corners of the grid square we're in, blend between them.
float lzNoise(vec2 p) {
  vec2 i = floor(p);                   // which grid square
  vec2 f = fract(p);                   // where inside it (0..1)
  vec2 u = f * f * (3.0 - 2.0 * f);    // ease the blend so the grid lines don't show
  return mix(
    mix(lzHash(i), lzHash(i + vec2(1.0, 0.0)), u.x),
    mix(lzHash(i + vec2(0.0, 1.0)), lzHash(i + vec2(1.0, 1.0)), u.x),
    u.y
  );
}

// 3. fbm ("fractal Brownian motion"): stack 4 layers, each twice as fine and half as strong.
float lzFbm(vec2 p) {
  float v = 0.0;
  float a = 0.5;
  for (int i = 0; i < 4; i++) {
    v += a * lzNoise(p);
    p = p * 2.03 + vec2(17.1, 9.2);    // finer detail, shifted so layers don't line up
    a *= 0.5;
  }
  return v;
}

Think of fbm like a coastline: big bays, smaller coves inside them, rocks inside those. One call gives you all the scales at once. The sea uses it for chop on the waves, the wobble of the surf lines, the whitecap patches and the cloud shadows.

The number you multiply the position by sets the size of the pattern. lzFbm(p * 0.012) gives blobs about 80 world units wide; lzFbm(p * 0.006) gives blobs twice as large.

Step 6

Waves without moving anything

This is the central trick. The plane stays perfectly flat, but we lie to the lighting about which way it faces.

Light reflects off a surface according to its normal, an arrow pointing straight out of it. A flat plane's normal points straight up everywhere, so it reflects like one big mirror. If each pixel gets a normal that tilts the way a wave's slope would tilt, the sun glint and sky reflection break up exactly as they would on real waves. At a distance your eye can't tell the difference.

First, a function that describes how high the water would be at any point:

// Height of the sea surface: a few long swells along the wind plus choppy noise.
float lzWaveHeight(vec2 p, vec2 dir, float t) {
  vec2 side = vec2(-dir.y, dir.x);     // 90° to the wind
  float h = 0.0;
  // three swells, each a bit off the wind direction, shorter, faster and smaller
  h += sin(dot(p, dir) * 0.018 - t * 0.9) * 1.0;
  h += sin(dot(p, normalize(dir + side * 0.6)) * 0.031 - t * 1.3) * 0.55;
  h += sin(dot(p, normalize(dir - side * 0.45)) * 0.047 - t * 1.7) * 0.35;
  // plus random chop drifting slowly downwind
  h += (lzFbm(p * 0.012 + dir * t * 0.05) - 0.5) * 2.2;
  return h;
}

Read one line like this: dot(p, dir) is how far downwind the point is. Multiply by 0.018 and the wave repeats every 2π / 0.018 ≈ 350 units. Subtract t * 0.9 and the crests slide forward as time passes. Three such waves at slightly different angles cross each other, so the sea never looks like corduroy.

Then the shader turns height into a normal. It asks for the height here, a little to the east, and a little to the south. The differences give the slope:

{
  // Fade wave detail with distance so far water doesn't shimmer, and calm it near the beach.
  float camDist = length(vLzWorld - cameraPosition);
  float amp = 8.0 * (1.0 / (1.0 + camDist / 6000.0)) * mix(0.35, 1.0, lzDepth);
  amp *= mix(0.6, 1.4, smoothstep(2.0, 12.0, lzWindSpeed));   // stronger wind, steeper waves

  vec2 p = vLzWorld.xz;
  float e = 4.0;                                       // look 4 units away
  float h0 = lzWaveHeight(p, lzWindDir, uTime);              // here
  float hx = lzWaveHeight(p + vec2(e, 0.0), lzWindDir, uTime);  // a step east
  float hz = lzWaveHeight(p + vec2(0.0, e), lzWindDir, uTime);  // a step south

  // slope east = (hx - h0) / e. Tilt the "up" arrow against the slope.
  vec3 worldNormal = normalize(vec3(-(hx - h0) / e * amp, 1.0, -(hz - h0) / e * amp));

  // three.js does its lighting in camera ("view") space, so convert before handing it back
  normal = normalize((viewMatrix * vec4(worldNormal, 0.0)).xyz);
}

A side view of lzWaveHeight along the wind. The line is the height the shader imagines; the arrows are the normals it hands to the lighting. The real plane stays flat. Turn amp up and the arrows lean harder, which is what a windy day does.

Two details make it look right from a paraglider's height:

  • Distance fade. Far away, one screen pixel covers many metres of sea, and detailed waves would flicker. amp shrinks as camDist grows, so the far sea calms into a smooth reflection of the sky, as it does in real life.
  • Calm shallows. lzDepth (next step) is 0 at the beach and 1 in deep water, so waves near the shore are about a third as steep.

Step 7

Turquoise shallows: knowing where the beach is

Shallow water over sand looks turquoise, deep water looks navy. To blend between them, each pixel needs to know how far it is from the nearest coast. Measuring that live for a million pixels would be far too slow, so it is measured once, when the island loads, and saved into a texture.

src/foundation/rendering/CoastField.ts

  1. A camera looks straight down at the island and renders it into an off-screen image: white where the ground is above sea level, black where it is sea.
  2. The pixels are read back into JavaScript, and a distance transform runs over them. It sweeps the image twice, top-left to bottom-right and back, and each sea pixel takes its neighbour's distance plus one step. After two sweeps every pixel holds its distance to the nearest land.
  3. The distances are packed into a greyscale DataTexture: 0 at the beach, 1 at 2,500 units or more out to sea.
// after the island has loaded (src/shared/TerrainBase.ts)
ocean.setCoast(bakeCoastField(renderer, island));

In the shader, a pixel converts its world position into a texture coordinate and reads its distance back:

// Distance to the nearest beach, in world units (uCoastMax far out at sea).
float lzCoastDistance(vec2 xz) {
  if (uHasCoast < 0.5) return uCoastMax;              // no island baked yet: open sea
  vec2 uv = (xz - uCoastBounds.xy) / uCoastBounds.zw;  // world position -> 0..1 on the texture
  uv.y = 1.0 - uv.y;
  if (any(lessThan(uv, vec2(0.0))) || any(greaterThan(uv, vec2(1.0)))) return uCoastMax;
  return texture2D(uCoast, uv).r * uCoastMax;          // 0..1 back to world units
}

Then the colour is just one smoothstep and one mix:

float lzCoast = lzCoastDistance(vLzWorld.xz);
float lzDepth = smoothstep(0.0, uShallowDistance, lzCoast);  // 0 at the beach, 1 out at sea
vec3 lzWater = mix(uShallow, diffuse, lzDepth);              // turquoise -> deep navy

diffuse is three.js's name for the material's color, the deep blue we passed to super(). uShallowDistance is 700 by default, so the turquoise fades out over about 700 metres. Both colours and the distance come from the theme (water.color, water.shallowColor, water.shallowDistance).

Why bake? Baking turns an expensive question ("where is the nearest land?") into a single texture read. This is one of the most useful habits in real-time graphics: work out anything that never changes once, ahead of time, and look it up per pixel.

Step 8

Surf, shore foam and whitecaps

Foam is a single number per pixel, lzFoam, from 0 (clear water) to 1 (solid white). Three sources feed it.

Surf lines rolling onto the beach

// Only in a band 15–140 units from the beach.
float lzSurfZone = 1.0 - smoothstep(15.0, 140.0, lzCoast);
// A sine wave of the coast distance makes rings parallel to the shore.
// "+ uTime * 1.6" makes them travel inwards; the fbm bends them so they're not perfect rings.
float lzSurfBand = sin(lzCoast * 0.11 + uTime * 1.6 + lzFbm(vLzWorld.xz * 0.01) * 6.0);
// Keep only the very tops of the sine wave, so you get thin white lines.
float lzSurf = lzSurfZone * smoothstep(0.75, 0.98, lzSurfBand) * 0.85;

This shows how much the coast distance is worth. Feed it to sin() and you get rings that follow the shape of every bay automatically, with no extra data.

The surf zone, 1.0 - smoothstep(edge0, edge1, lzCoast), plotted against distance from the beach. The faint line is the surf band inside it at time 0. Drag the edges to see how smoothstep sets where an effect starts and ends.

A white rim right at the water's edge

float lzShoreFoam = (1.0 - smoothstep(0.0, 18.0, lzCoast)) * 0.9;

Whitecaps out at sea

// Big, slowly drifting noise patches...
float lzCapNoise = lzFbm(vLzWorld.xz * 0.006 - lzWindDir * uTime * 0.35);
// ...but only the highest peaks turn white. More wind lowers the bar, so more caps appear.
float lzCapThreshold = mix(0.95, 0.72, smoothstep(3.0, 12.0, lzWindSpeed));
float lzCaps = smoothstep(lzCapThreshold, lzCapThreshold + 0.05, lzCapNoise) * lzDepth;

Thresholding noise is a classic trick: noise is a landscape of hills, and smoothstep with a high edge keeps only the summits. Lowering the threshold floods fewer hills, so more islands of white show. Try the wind slider in the demo.

Combine and paint

lzFoam = clamp(max(max(lzSurf, lzShoreFoam), lzCaps * 0.8) * uHasCoast
             + lzCaps * (1.0 - uHasCoast), 0.0, 1.0);
vec4 diffuseColor = vec4(mix(lzWater, vec3(0.92, 0.95, 0.96), lzFoam), opacity);

max() takes whichever foam is strongest, so overlapping sources don't add up to something brighter than white. The uHasCoast part means: before the island is baked, show whitecaps only. The last line is the line we replaced in step 2. three.js lights diffuseColor as if it had always been its own.

Step 9

Finishing touches: matte foam and cloud shadows

// after three.js works out roughness: foam is rough (0.85), open water stays glossy
roughnessFactor = mix(roughnessFactor, 0.85, lzFoam);

// after all lighting: darken under drifting clouds
outgoingLight *= lzCloudShadow(vLzWorld.xz);

Real foam doesn't mirror the sun, so foamy pixels get a high roughness and lose the glint. Cloud shadows are one more fbm, scaled to cloud size and slid downwind over time:

float lzCloudShadow(vec2 worldXZ) {
  vec2 p = (worldXZ - uWind * uTime * 8.0) / 2600.0;   // patches ~2.6 km wide, moving with the wind
  float c = smoothstep(0.52, 0.72, lzFbm(p));          // keep the bigger blobs, soft edges
  return 1.0 - c * uCloudShadow;                        // 1 = full light, less under a cloud
}

The same function is patched into the terrain material via addCloudShadows(). Since both read the same uTime and uWind, a shadow slides off the sea and up the cliffs without a seam.

Recap

The whole recipe on one page

  1. One flat plane with a shiny MeshStandardMaterial, so sky reflections and sun glint come for free.
  2. onBeforeCompile plus .replace() slips our GLSL into three.js's own shader.
  3. The vertex shader passes each pixel its world position.
  4. A shared clock and wind, updated from JavaScript each frame, drive all motion.
  5. Fake waves: sum of sines plus noise gives a height; the slope of that height becomes the normal.
  6. A coast-distance texture, baked once, drives the shallows, the surf rings and the calm near the shore.
  7. Foam comes from thresholded sines and noise, painted white and made matte.
  8. Cloud shadows darken the final colour.

If you want to experiment, the safest knobs are the plain numbers. Each one maps to something you can see:

Change thisAnd you get
0.018, 0.031, 0.047Longer or shorter swells (smaller number, longer wave)
t * 0.9, t * 1.3 …Faster or slower wave travel
8.0 in ampRougher or glassier sea
15.0, 140.0 in lzSurfZoneWhere the surf breaks

0.95, 0.72 in lzCapThresholdHow many whitecaps on calm and windy days

Debugging tip. When something looks wrong, paint the suspect value as a colour. Temporarily set diffuseColor = vec4(vec3(lzDepth), 1.0); and the sea turns into a black-to-white map of depth. It is the shader version of console.log.
